ML-overlay-problem · case study

Separating red from green when they live in the same place

1,672 points, two colours, one plane. Fifteen-plus clustering methods were tried in this repo and most landed on almost exactly the same F1 score. This page explains why, shows that a one-line score with no labels (how far a point is from its neighbours) beats them all, and lets you run every idea live on the real dataset. A second dataset (switch it at the top right) keeps the same footprint but draws red from a Gaussian and green from a uniform distribution, which shows what changes when the classes really are different.

The problem


Each row of df_red_green_overlay.csv is an (X, Y) coordinate with a colour. The task is to recover the colour without using it. That's hard because, viewed as whole populations, the two colours have the same shape.

The 0.239 trap

Label every point red. Precision becomes the red share p = 0.136 and recall becomes 1. The resulting F1 is the number that DBSCAN, t-SNE + DBSCAN, ICA + DBSCAN and the density-ratio method all reported in the notebook.

F1all red = 2p / (1 + p) = 0.2391

More generally, if a method flags a fraction q of points at random, precision stays at p and recall equals q, so F1 = 2pq / (p + q). Every random guesser sits on this curve. A method has to beat it at the same q before it can claim to have learned anything.

Where the signal actually is

On the original dataset: globally, the classes overlap completely. Locally, they don't. Red points tend to sit in slightly emptier spots, and they tend to sit next to other reds. LNND (the best label-free method in the notebook) and the supervised SVM both exploit this.

Share of red among the k nearest neighbours

Original dataset: the simplest score wins. Rank points by the distance to their k-th nearest neighbour and flag the 227 sparsest. No labels are used, and F1 is 0.39 at k = 10 and 0.46 at k = 5. That ties or beats the notebook's supervised RBF-SVM (test F1 0.41) and is far above LNND (0.295). Most red points are simply points in sparse spots. Try it in the lab under “k-NN distance”.

A dataset with distinct distributions

make_distinct_dataset.py writes df_red_green_distinct.csv, keeping the original footprint: every location within 45 px of an original point. Inside it, green is a homogeneous Poisson process (uniform density, count ~ Poisson(1445), which came out as 1,477). Red is 227 draws from an isotropic Gaussian with σ = 90 px, centred at (1046, 904). The classes still overlap: at the centre there are about 6 red points per green one, but green dominates the tails. So even the Bayes-optimal classifier, which knows the true generator, tops out at F1 ≈ 0.75.

Does t-SNE work now?

Partly. With eps ≈ 3.75 and min_samples = 20, DBSCAN on the t-SNE map finds a cluster that is mostly red: F1 ≈ 0.64, against 0.24 on the original data. There are three catches:

  1. Picking the red cluster needs labels. DBSCAN returns 10–15 clusters. Label-free rules (the largest cluster, or the densest one) pick the wrong one.
  2. It's fragile. At min_samples = 20, eps = 3 gives 0.34, eps = 4 gives 0.59, and eps = 5 gives 0.36.
  3. t-SNE erases density. Perplexity gives every point the same effective number of neighbours, so the Gaussian bump that defines red gets flattened. k-NN density computed on the t-SNE map scores F1 0.12, against 0.73 for the same score in raw X–Y.

So t-SNE is a good way to see the structure (try the “t-SNE map” view in the lab), but it isn't a good way to classify it. Density estimation in the original space (k-NN density, or a Gaussian + uniform mixture) does better, scoring close to the Bayes ceiling.

Repository map

What each file contains, plus the issues found while reading it.

case_study-unsupervised-overlay-problem.ipynb

The main study, written to run in Colab. It covers DBSCAN, agglomerative clustering, NumPy Fuzzy C-Means, t-SNE, spectral clustering, ICA + polynomial features, KDE density ratio, a Poincaré-disk hyperbolic graph and GCN, supervised LogReg/RF/GB/SVM with threshold and cost tuning, OCSVM, and LNND.

The hyperbolic GCN cell logs “does not require grad” on every epoch, so the 0.26 F1 comes from an untrained model.

README.md

A guide to which methods to use for overlapping clusters: GMM, spectral with RBF, threshold tuning, LOF + GMM, multi-metric spectral, feature augmentation, and ensembles.

It promises F1 of 0.6–0.8+ and gains of 30–50% over K-Means. Nothing in the repo reaches those numbers on this dataset. It also calls fit_predict_proba, which isn't a scikit-learn method.

overlay_clustering_advanced.py

Seven methods in one script: GMM, spectral with RBF, kernel K-Means, two-stage Isolation Forest, EM with a spatial constraint, density-based soft assignment, and a voting ensemble. Each prints F1, precision, recall and a confusion matrix.

overlay_advanced_tuning.py

Tuning tools: BIC/AIC for GMM, a gamma search for spectral clustering, LOF weighting, multi-metric spectral, KDE mixtures, bootstrap consensus, and checks for correlation with the coordinates.

Line 115 calls gmm.fit_predict_proba(X), which raises AttributeError.

quickstart_colab.py

A copy-paste Colab template: GMM (full covariance, n_init=30), a threshold search with minimize_scalar, comparison plots, and CSV export.

The threshold is tuned against true_labels. That is supervised selection, and the F1 it reports is optimistic.

make_distinct_dataset.py → df_red_green_distinct.csv

Generates the second dataset (seed 42), with the same footprint, a Gaussian red and a uniform (Poisson) green. The t-SNE maps used on this page come from TSNE(perplexity=30, init="pca", random_state=42) on standardised X, Y.

df_red_green_overlay.csv

1,672 rows with columns X, Y, Color, Type. Type is redundant: cross means light_green and point means red. Coordinates are integers between about 37 and 1,940.

Takeaways

  1. Always report the trivial baseline. On this data, “everything is red” scores F1 = 0.239. About half of the notebook's results are within ±0.02 of it.
  2. Global-blob methods can't work here. The class means and covariances are nearly identical, so K-Means, GMM, FCM, spectral and agglomerative clustering split the plane geometrically, not by colour. Try GMM and FCM in the lab: they cut the cloud in half.
  3. Frame it as local sparsity detection. Red points sit in emptier spots. The raw k-NN distance (F1 0.39–0.46) beats LOF (0.32–0.33) and LNND (0.28–0.30). Those methods divide by the neighbours' density, and that normalisation removes the very signal that separates the classes.
  4. Watch for label leakage. Several “unsupervised” scores were chosen by maximising F1 against the true labels: the cluster-to-colour mapping, LNND's k, the GMM threshold in the quickstart, and OCSVM trained only on greens. Hold out labels for these choices, or pick them with an unsupervised criterion.
  5. Know the ceiling. Supervised models (SVM 0.41, leave-one-out k-NN up to about 0.47) barely beat the label-free k-NN distance. X and Y carry little more information than that. If you need more, add features (the source image? other attributes?) rather than a more exotic clustering algorithm.
  6. Change the data and the right tools appear. When red is a Gaussian and green is uniform, k-NN density (≈ 0.73) and a Gaussian + uniform mixture get close to the Bayes ceiling (≈ 0.75). A 2-component GMM still fails, because it assumes the wrong model. t-SNE + DBSCAN reaches about 0.64, but only with tuning and a cluster chosen using labels.
  7. Compare with the PR curve, not one F1. For a rare class, average precision and F1 vs. fraction flagged (as in the lab) show whether a score really ranks reds above greens.
